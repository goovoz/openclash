# 08 旁路由部署指南

> 状态：验证通过（2026-10-02，Debian 12 真机全链路）
> 前置：`openclash-rt` 包已安装（`dpkg -i`），P1~P5 已交付

## 1. 什么是旁路由

OpenClash 原本为 OpenWrt 路由器设计（它假定自己是网关，有 lan + wan）。
本项目的目标是把 OpenClash 移植到**任意 Debian/Ubuntu 无桌面服务器**，最常见
的落地场景就是**旁路由**：

- 一台跑 Debian 的服务器（本机）作为旁路由，IP 如 `172.20.0.101`
- 局域网其他设备的网关/DNS 指到这台旁路由
- 旁路由通过 OpenClash 的 mihomo 内核透明代理，让局域网设备科学上网
- 旁路由自身也翻墙（上面可能还跑其他需要翻墙的服务）

## 2. 端口布局（底层保持上游默认，唯一改动是 luci-host 让位）

| 端口 | 归属 | 监听 | 说明 |
|---|---|---|---|
| **9080** | luci-host（自建 HTTP 宿主） | `0.0.0.0` | Web 管理界面，局域网设备访问 |
| **9090** | mihomo external-controller | `*` | 内核控制 API（上游 `cn_port` 默认，不动） |
| 7874 | mihomo DNS | `*` | DNS 劫持目标（上游 `dns_port` 默认） |
| 7890 | mihomo HTTP proxy | `*` | 显式 HTTP 代理 |
| 7891 | mihomo SOCKS proxy | `*` | 显式 SOCKS 代理 |
| 7892 | mihomo redir | `*` | 透明代理 TCP 重定向目标 |
| 7893 | mihomo mixed | `*` | 显式混合代理（HTTP+SOCKS） |
| 7895 | mihomo tproxy | `*` | 透明代理 UDP tproxy 目标 |

> 为什么 luci-host 用 9080 而不是 9090：9090 是 mihomo external-controller 的
> 上游默认端口，底层保持上游一致、避免同步上游时冲突，宿主让位到 9080。

## 3. 安装

```bash
# 1) 安装依赖（Depends 会自动拉，但显式装一遍更稳）
apt-get install -y jq net-tools ipcalc bind9-dnsutils dnsmasq nftables

# 2) 安装包
dpkg -i openclash-rt_*.deb

# 3) 启动服务
systemctl start openclash-rt-luci-host   # Web 管理界面（9080)
```

### 3.1 必须配置：出网代理（若本机不能直连 GitHub）

OpenClash 的**内核下载**与**订阅更新**都要访问 GitHub。若本机直连不通
（表现为 UI 点下载后日志出现 `Core Version Check Error`，且 10 秒内返回），
必须给宿主进程注入代理环境。

```bash
# 1) 建代理环境文件。注意用**裸 KEY=value**，systemd EnvironmentFile
#    不支持 export 前缀（写了 export 会静默不生效）。
cat >/etc/default/openclash-proxy <<EOF
http_proxy=http://<代理IP>:<端口>
https_proxy=http://<代理IP>:<端口>
HTTP_PROXY=http://<代理IP>:<端口>
HTTPS_PROXY=http://<代理IP>:<端口>
EOF
chmod 0644 /etc/default/openclash-proxy

# 2) 让宿主 service 读取它
#    [Service] 段下加一行（注意加在 [Service] 之后、Type= 之前均可）：
#      EnvironmentFile=-/etc/default/openclash-proxy
systemctl daemon-reload
systemctl restart openclash-rt-luci-host

# 3) 验证代理确实进了宿主进程环境
PID=$(pgrep -f 'lua5.1 /usr/lib/openclash-rt/luci-host.lua' | head -1)
tr '\0' '\n' <"/proc/$PID/environ" | grep -i proxy
```

> **为什么必须注入到宿主而不是当前 shell**：LuCI 宿主对每个请求
> `fork` 一个 CGI 子进程，子进程只继承**宿主**的环境。在 SSH 里
> `export https_proxy=...` 后直接跑 `/usr/share/openclash/openclash_core.sh`
> 能成功，但点 UI 按钮依然失败—— 因为 CGI 子进程看不到你 shell 里的变量。
> 这是 2026-10-02 真机实测踩过的坑。

也可在 LuCI 的「覆盖设置 → 常规设置 → GitHub 加速」里选 CDN 前缀
（对应 UCI 项 `github_address_mod`），但那是**上游自带的绕行方案**，
覆盖面不如代理广（订阅更新、规则更新仍可能失败）。

## 4. 首次配置（在 LuCI 界面操作）

浏览器打开 `http://<旁路由IP>:9080`，默认账号 `root`、密码是**系统 root 密码**。

### 4.1 下载 mihomo 内核

「插件设置 → 版本更新 → 内核更新」，或手动：

```bash
# 内核从 GitHub 下载，大文件（~12.5MB）容易截断，用断点续传：
TARGET=13170872
for i in $(seq 1 20); do
  curl -s -m 20 -C - -o /tmp/clash_meta.tar.gz \
    "https://raw.githubusercontent.com/vernesong/OpenClash/core/master/meta/clash-linux-amd64-v3.tar.gz"
  [ "$(stat -c %s /tmp/clash_meta.tar.gz 2>/dev/null || echo 0)" -ge "$TARGET" ] && break
done
tar -xzf /tmp/clash_meta.tar.gz -C /tmp/
mv /tmp/clash /etc/openclash/core/clash_meta
chmod 0755 /etc/openclash/core/clash_meta
ln -sf /etc/openclash/core/clash_meta /etc/openclash/clash
```

### 4.2 添加订阅

「配置订阅」页添加订阅 URL。以 pqjc 为例：

```
订阅地址：https://...（机场订阅 URL）
转换方式：在线转换（sub_convert=1）
转换服务：https://api.asailor.org/sub
模板：default_with_clash_adg
```

保存后点「更新全部订阅」，OpenClash 会把 base64 URI 订阅转成完整 YAML 配置。

### 4.3 开启旁路由必需的 5 个选项

这些都在上游默认值之外，需在 LuCI 界面（或命令行）按旁路由场景开启：

| 选项 | 值 | 为什么 |
|---|---|---|
| `enable` | 1 | 开启 OpenClash（默认关闭） |
| `enable_meta_sniffer` | 1 | **嗅探**。fake-ip + redirect 透明代理必须，否则内核无法从 TLS 还原域名，透明代理 SSL 握手失败（显式代理不受影响） |
| `enable_redirect_dns` | 2 | **DNS 防火墙重定向**。绕开 dnsmasq 与 systemd-resolved 抢 53 端口的冲突，纯 nft 把 53 重定向到内核 7874 |
| `router_self_proxy` | 1 | 旁路由自身也翻墙（上游默认就是 1，保持即可） |

> 第 5 项「IP 转发」无需手动配：`prepare-tmp.sh` 已在每次服务启动时自动开启
> `net.ipv4.ip_forward=1`（旁路由转发局域网流量的前提）。

命令行等价操作：

```bash
uci set openclash.config.enable=1
uci set openclash.config.enable_meta_sniffer=1
uci set openclash.config.enable_redirect_dns=2
uci set openclash.config.router_self_proxy=1
uci commit openclash
/etc/init.d/openclash restart
```

### 4.4 修正 LAN IP

OpenWrt 默认 LAN 是 `192.168.1.1`，旁路由需改成自己的真实 IP，否则内核就绪
检查会连不上控制 API 导致启动失败：

```bash
uci set network.lan.ipaddr=<旁路由真实IP>   # 如 172.20.0.101
uci commit network
```

## 5. 验证（全链路）

```bash
# 1) 内核稳定运行（不被 watchdog 误杀）
pidof clash && echo OK

# 2) DNS 劫持 fake-ip
dig @127.0.0.1 google.com A +short   # 应返回 198.18.0.x

# 3) 透明代理（本机直连，router_self_proxy=1）
curl -s -m 15 https://www.google.com -o /dev/null -w "%{http_code}\n"   # 302

# 4) 显式代理
curl -s -m 15 -x http://127.0.0.1:7893 https://www.google.com -o /dev/null -w "%{http_code}\n"  # 302

# 5) Web 界面局域网访问
curl -s -m 5 http://<旁路由IP>:9080/ -o /dev/null -w "%{http_code}\n"  # 302
```

## 6. 让局域网设备走旁路由

在**其他设备**上（或 DHCP 下发）：

- **网关**指向旁路由 IP（`172.20.0.101`）
- **DNS** 指向旁路由 IP（DNS 请求会被 nft 重定向到内核 7874，返回 fake-ip）

或者手动在某台设备上改网关 + DNS 验证透明代理。

## 7. 已知限制 / 待办

- **内核下载依赖 GitHub**：大文件会截断，需断点续传（见 4.1）。生产环境建议
  提前下好内核放进镜像，或配置 GitHub 加速镜像（`github_address_mod`）。
- **WAN zone 警告**：启动日志会报「Can't Setting Only Intranet Allowed...
  WAN Interfaces error」，因为旁路由没有 wan zone，属预期，可忽略（不影响透明代理）。
- **跨设备透明代理**：本文验证的是旁路由自身透明代理；局域网设备把网关指过来
  的完整链路待实机复测（见下一轮）。
- **DNS 残留缓存**：`getent hosts` 可能返回旧的 fake-ip，属正常，重新解析即可。

## 8. 排障速查

| 症状 | 根因 | 修法 |
|---|---|---|
| 内核启动后 15 秒被杀，`enable` 变 0 | watchdog 用 `ubus call service list` 检查内核，但无真 procd 的 service 对象 | 已内置 ubus 垫片；确认 `/usr/bin/ubus` 是垫片、`/usr/lib/openclash-rt/ubus.real` 是真客户端 |
| 透明代理 SSL 握手失败，显式代理正常 | sniffer 未开启 | `enable_meta_sniffer=1` |
| 本机直连外网全挂（github SSL 失败） | fake-ip 数据面没通 + router_self_proxy=1 劫持了自身 | 先确认 sniffer 已开、DNS 劫持生效 |
| DNS 不返回 fake-ip | DNS 重定向规则没写入（brace expansion 破坏 nft 语法） | 确认 rc.common 已含 `set +B` |
| `nft` 报 `unexpected th` | bash brace expansion 把 `{tcp,udp}` 展开成 `tcp udp` | rc.common 的 `set +B` 修复 |
| UI 点「更新内核」秒回，日志 `Core Version Check Error` | 本机不能直连 GitHub，版本查询拿不到 `core_meta` 版本号 | 见 §3.1 配 `EnvironmentFile` 代理。**注意**：在 SSH 里 export 没用，必须注入宿主 service |
| `sub_info_get` 返回 500 且响应体为空 | 一个 `config_subscribe` 段都没有时上游的边界条件（`uci:foreach` 空转后继续走 `get_sub_url`） | 加任意一个订阅段即恢复。上游问题，不影响正常使用 |
| 打开 `other-file-edit` 跳到 URL 里带字面量 `%s` | 未传 `?file=` 且无 `Referer` 头，上游 `build_url(...) % arg[1]` 里 `arg[1]` 为 nil | 正常入口从菜单点进去会自带参数；手敲 URL 需补 `?file=<绝对路径>` |
| `other-rules-edit` 报 `Model not found` | 上游注册了该路由但 `luasrc/model/cbi/openclash/other-rules-edit.lua` **不存在** | 上游自身死链（且菜单标题为 `nil` 无入口），无法从 UI 到达。已知降级项 |
