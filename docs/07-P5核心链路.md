# P5 核心链路：让 OpenClash 在 Debian 上真正跑起来

> 状态：摸底完成，方案已定，实施中
> 日期：2026-10-02

## 1. P5 的目标

P1~P4 打通了「包装、可安装、Web UI 能登录、能进 openclash 页面」。
P5 的目标是验证**核心功能链路**：`/etc/init.d/openclash start` 能真正拉起
mihomo 内核，跑通「内核下载 → 配置加载 → 进程常驻 → 控制端口监听」。

这是"页面真正可用"的最后一道关——之前所有阶段都在解决"能不能装上、能不能
登录"，P5 解决"装上之后它到底能不能干活"。

## 2. 启动链路全貌（已实测打通到 Config Not Found）

`/etc/init.d/openclash` 的调用链：

```
boot() → restart() → stop_service() → start() → start_service()
                                                      │
                          enable != 1 ────────────────┘ exit（默认关闭）
                          enable == 1 ↓
                     procd_open_instance("openclash")
                     exec $CLASH -d $CLASH_CONFIG -f $CONFIG_FILE
                        ↓
              CLASH = /etc/openclash/clash（软链到 core/clash_meta）
              CLASH_CONFIG = /etc/openclash
              CONFIG_FILE = /etc/openclash/<订阅名>.yaml
```

### 启动的两个硬前置条件（实测确认）

1. **`enable=1`**：`uci set openclash.config.enable=1`，否则
   `start_service()` 第 3596 行直接 `LOG_WARN ... Exit`。
2. **存在配置文件**：`/etc/openclash/config/*.yaml`，否则
   `get_config()` 第 418 行 `LOG_ERROR "Config Not Found"` 退出。

## 4. jsonfilter 垫片（P5 核心新件）

上游 3 个脚本用 `jsonfilter`，两种形态：

```sh
# 形态 A：文件查询（openclash_core.sh / openclash_update.sh）
jsonfilter -i /tmp/openclash_version_history.json -e '@.master.latest.core_meta'

# 形态 B：stdin 管道（openclash_update.sh:442 / openclash_watchdog.sh:211）
ubus call service list '{...}' | jsonfilter -e '@.openclash.instances.*.running'
```

两者都能用 `jq` 替代。垫片要点：

- `-i <file>` → `jq -r '<expr>' <file>`
- stdin → `jq -r '<expr>'`
- 表达式 `@.a.b.c` → `.a.b.c`（去 `@` 前缀）
- `.*` 通配 → `.a.b.c[]` 或 `.a.b.c`（jq 的 `.*` 语义不同，需映射）
- `-e` 是表达式（可多个 `-e`），`-l` 是长度（暂不需要）

**注意**：`@.openclash.instances.*.running` 里的 `.*` 是"任意一层"，jq 需改成
`.openclash.instances[]?.running`（OpenWrt jsonfilter 的 `*` 是通配任意键/数组）。

## 5. mihomo 内核获取

内核从 `https://github.com/vernesong/OpenClash@core/master/meta/clash-<arch>.tar.gz`
下载，架构由 `core_version` 配置决定（amd64 → linux-amd64）。

正常流程依赖 `jsonfilter` 解析版本号 → 下载 → 解压到 `/etc/openclash/core/clash_meta`
→ 软链 `/etc/openclash/clash`。

## 6. 验证判据（P5 完成标准）

### 关键踩坑

1. **内核下载大文件必截断**：真机到 raw.githubusercontent.com 传 1.3MB 就断
   （curl/wget/jsdelivr/代理 都一样）。修法：`curl -C -` 断点续传循环直到
   `size == Content-Length`（真实大小 13170872 字节）。
2. **`sh: 33: export: Illegal option -n`**：Step 3 阶段出现 4 次，来自 overwrite
   模块第 3217 行 `export ${varname}=${v_escaped}`，dash 把某变量名当成了 `-n`
   选项。**不阻塞内核启动**，记录为已知问题待深挖。

## 9. 待确认风险

- **内核下载需联网 GitHub**：真机能直连但大文件会截断（见 §8 踩坑 1）。内核
  二进制（12.5MB）是否应打包进 .deb？建议不打包（与上游一致走运行时下载），
  但需在文档里提示断点续传。
- **`fw4`/`nft` 防火墙规则**：OpenClash 启动会写大量 nftables 规则（透明代理）。
  我们的 fw4 垫片目前是"让 command -v 成功"的最小实现，能否承载真实规则写入
  是 P5 后期要验证的重头。
- **dnsmasq 劫持**：OpenClash 会改 dnsmasq 配置做 DNS 劫持，Debian 上 dnsmasq
  的行为差异需验证。
