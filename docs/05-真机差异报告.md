# 05 · 真机差异报告：MSYS 推演 vs Debian 12 实测

> **状态**：本轮新发现。作业 P1-P2 + L2-L5 全在 MSYS 上**纸面跑通**，但真机集成时
> 暴露 33 个测试 FAIL + 11 个 build 链 bug + 4 个 deb 布局/配置 bug。
> 本文件是它们的**统一归口**——根因、证据、修复、留给上游同步的 checklist。

## 1. 环境差异源头

| 维度              | MSYS（开发机）                            | Debian 12（真机）                            |
| --------------- | -------------------------------------- | ----------------------------------------- |
| shell 解释器 | Git Bash 4.x（MSYS2 fork）                 | dash 0.5.x + bash 5.1                       |
| 行尾              | CRLF（git autocrlf=true）                | LF（POSIX）                                  |
| `file` 命令       | 无 `file` 二进制（需用 `od`/`grep -U` 替代）    | GNU file 5.6                               |
| awk             | GNU gawk / mawk 都见过                       | mawk 1.3.4（Debian 默认）                       |
| grep -E + `\t`  | MSYS grep 默认识别 `\t`                    | GNU grep 3.8 在 ERE 下**不**识别 `\t`，需 `[[:space:]]` |
| `dpkg-architecture` | 缺（MSYS 无）                            | 存在，返回 `x86_64-linux-gnu`                    |
| 真机系统调用          | MSYS 路径转换、管道自动 LF 规范化                  | POSIX 严格按字节流转                          |

`MSYS 会被掩盖的真问题` = `mr-wins-mask`。本轮 33 个 FAIL 全属此类。

## 3. 33 个真机 FAIL 的根因分类

### 3.1 CRLF 在 awk 正则里死锁（17 个）—— `runtime/lua/lib/upstream-parsers.sh`

| 函数            | 真机症状                                | 根因                                       |
| ------------- | ----------------------------------- | ---------------------------------------- |
| `_cmake_setlist` | 抽不出 `.cpp = attr.c ...`             | `\r` 把行尾打回记录：awk `cap=0` 判断条件 `$0 ~ /\)/` 不再成立（行的真实内容是 ` )\r`） |
| `_cmake_addlib` | 同上                                  | 同上                                       |
| `_make_varlist` | NIXIO_OBJ 抽空                        | `\r` 混进 make 续行 `\\&`，`sub(/\\/)` 后残留 `\r` |

**修法**：三个 awk 段加 `BEGIN{RS="\r?\n"}`，awk 自带按字节流解析行；上游代码原意
是单 `\n` 行，但 Windows checkout 把它转成 `\r\n`，**不被解析** = **被错误地"吞掉"**。

### 3.2 CRLF 在 sh 解析里死锁（12 个）—— `tests/test_openwrt_release.sh`

上游 `uci-defaults/luci-openclash` 用 `case "${DISTRIB_ARCH}" in ... esac`。
测试用 awk 抽这段后**直接喂给 dash 解析**，awk 保留的 `\r` 让 dash 把 `in\r`
当 keyword 解析失败。

**修法**：抽出后 `tr -d '\r'`，再生成 `upstream_core_arch.sh`。

### 3.3 CRLF 让 `head -1` 留 `\r`（9 个）—— `tests/test_pin_lua.sh`

`$(head -1 "$file")` 在 MSYS 管道自动规范化 `\r`；Debian head 保留 → chk 断言
长 1 字节。

**修法**：批量 `sed 's|$(head -1 "\1")|$(head -1 "\1" | tr -d '\''\r'\'')|'`。

### 3.4 `dpkg-architecture` mock 缺失（1 个）—— `tests/test_lua_path_bridge.sh`

真机 `dpkg-architecture -qDEB_HOST_MULTIARCH` 返回 `x86_64-linux-gnu`，桥接逻辑
正确触发，但测试假设"`DEB_HOST_MULTIARCH=""` 必然退化到 5 条软链"——前提是 mock
掉 dpkg-architecture。

**修法**：测试加 `dpkg-architecture` 假二进制目录，模拟"系统不存在 dpkg-architecture"
的场景，确保单一事实来源不被环境依赖。

### 3.5 `got` 语义 bug（1 个）—— `tests/test_maintainer_scripts.sh`

A 组 `_case` 用 `if [ ! -e "$SB_ROOT/uci" ] && [ ! -L "$SB_ROOT/uci" ]` 判 gone。
但用例 6/7 是"`$SB_ROOT/uci` 从未存在"，got 永远 gone（与 cleanup 调用无关）。

**修法**：改成比对 setup 前后状态（`before/after` snapshot）。

### 3.6 B2 用错 LIST（1 个）—— `tests/test_lua_parsers.sh`

```bash
chk "B2 未把 multiarch 硬编码成 x86_64（必须由探测决定）" \
    "$(printf '%s\n' "$LIST" | grep -c 'x86_64-linux-gnu')" "0"
```

应该查 `LIST2`（应用代码实际消费的探测结果），不是 `LIST`（假设探测）。

## 6. CRLF —— 今日最大的隐藏雷

**根因**：上游/vendor 工作树用 `git clone` + Windows `core.autocrlf=true`，
所有文本文件被 checkout 为 CRLF。MSYS tar 创建归档时只编码**部分**文件，
行为不可预测，导致"本地 CRLF → 远程有时 LF 有时 CRLF"。

**正确处置**（**已修**）：

1. **一次性物理规范化**：本地树 1228 个文本文件 `sed -i 's/\r$//'`。
3. **构建期防线**（build-deb.sh §1z）：staging 上的 `/etc/init.d/*`、`/etc/uci-defaults/*`、
   `*.sh` 就地剥 CRLF（vendor 编译副本由 `bc_copy_src` 同款剥 `\r\()`）。
5. **po 源**（§5e）：先 sed 再喂 po2lmo —— 否则 \r 混进 msgid/msgstr。
6. **lua/htm** 不剥：Lua 5.1 lexer 与 LuCI 模板引擎都把 `\r` 当空白，无害。

### P3 调试踩到的 4 个 Lua 5.1 + 时间语义雷区

| # | 现象 | 根因 | 修 |
|---|---|---|---|
| 1 | B2/D2 全 FAIL：body 不含 env vars，header 多出 `HTTP_HOST=127.0.0.1: ...` | Lua 5.1 `io.read("*l")` 读 `\r\n` 时**保留 `\r`**，空行 `\r\n` 读成 `"\r"`（非空）→ 循环不 break，正文被吞成 header | 每行 `gsub("\r$", "")` 后再判断空 |
| 2 | C1 FAIL：Lua 抛 "field 'day' missing in date table" | `string.match` 7 capture 接 6 变量，Lua 从末尾截断 → `d = "Thu"`（weekday）而非 `"01"`（day） | 必须用 7 个变量接，第 1 个用 `_` 丢弃 weekday |
| 3 | C1 IMS=mtime FAIL（与 #2 同时）| Lua 5.1 `os.time({hour=15})` 给的是 15:00 CST 的 epoch（= 07:00 UTC），差 8h。`os.execute("export TZ=UTC")` 只改子进程**不影响父进程** | 用 `date -u -d <args> +%s` 子进程算 UTC epoch |
| 4 | C1 IMS=mtime FAIL（与 #3 同时）| 文件系统 mtime 是亚秒精度（1790869024.692），IMS 头解到 1790869024（截断到秒），直比 `mt <= since` 因 0.692s 亚秒必 false | `mts = math.floor(mt)` 截到秒后比 |
